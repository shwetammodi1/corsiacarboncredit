# corsiacarboncredit.in

Carbon credit marketplace, CORSIA advisory and knowledge base, run by DSTechnoverse.

## Run it

```
npm install
npm run dev        # builds to dist/ and serves it at http://localhost:4321
npm run build      # build only
```

`dist/` is plain static HTML.

## Deploy

Hosted on Cloudflare Pages as the project `corsiacarboncredit`, served at https://corsiacarboncredit.in.

The project is connected to this GitHub repo. Every push to `main` builds and publishes the site. Pushes to other branches get a preview URL.

```
git push           # Cloudflare runs `npm run build` and publishes dist/
```

Cloudflare build settings: build command `npm run build`, output directory `dist`, environment variable `NODE_VERSION=22`.

Don't upload from your machine with `wrangler pages deploy`. The next push would replace whatever you uploaded.

### One address

`functions/_middleware.js` sends `www.corsiacarboncredit.in` and `corsiacarboncredit.pages.dev` to `https://corsiacarboncredit.in` with a 301, keeping the path. Preview deployments (`<hash>.corsiacarboncredit.pages.dev`) are not redirected. For www to reach the site at all, `www.corsiacarboncredit.in` must be added under the Pages project's Custom domains.

HTTP to HTTPS is handled by Cloudflare ("Always Use HTTPS").

## SEO

| What | Where |
|---|---|
| Canonical domain (canonical tags, sitemap, robots.txt, Open Graph, schema) | `url` in `src/data/site.js` |
| Title and meta description of the main pages | `src/data/seo.js` |
| Title and meta description of an article | `metaTitle` / `metaDescription` in the article's front matter (optional; defaults to `title` / `excerpt`) |
| Sitemap and robots.txt | generated by `build.mjs` into `dist/` on every build |

Structured data on every page: Organization and WebSite, plus BreadcrumbList on inner pages. Blog posts carry BlogPosting, knowledge base articles TechArticle, topic pages CollectionPage. FAQPage is only on pages whose content is a list of questions: `/services/` and `/knowledge-base/marketplace-faq/` (`FAQ_PAGES` in `build.mjs`). Article dates come from the front matter `date` and the file's git history.

## Adding blog posts and knowledge base articles

Step-by-step guide for editors (in Hinglish): [docs/CONTENT-GUIDE.md](docs/CONTENT-GUIDE.md).

Two sources are merged at build time:

1. **Markdown** in `src/content/insights/` (blog posts, published at `/blog/<slug>/`) and `src/content/knowledge-base/`. Copy `_template.md` in either folder; files starting with `_` are not published.
2. **Sanity**, when `SANITY_PROJECT_ID` is set in the Cloudflare Pages environment. `src/lib/sanity.mjs` fetches published `blog` and `kbArticle` documents and converts their Portable Text to markdown, so they go through the same renderer. A Sanity document with the same slug as a markdown file replaces it. If Sanity is configured but unreachable the build fails, so the last good deployment stays live.

| Variable | Default | |
|---|---|---|
| `SANITY_PROJECT_ID` | — | switches Sanity on |
| `SANITY_DATASET` | `production` | use `corsia` |
| `SANITY_TOKEN` | — | only for a private dataset (Viewer token) |
| `SANITY_BLOG_TYPE` / `SANITY_KB_TYPE` | `blog` / `kbArticle` | document type names |

The Sanity Studio (schema for both types, with topic/section dropdowns and SEO fields) is in `studio/`. Run `npm install && npm run dev` there; `npm run deploy` publishes it to https://corsiacarboncredit.sanity.studio. Publishing in Sanity can trigger a rebuild through a Sanity webhook pointed at a Cloudflare Pages deploy hook.

## Where to edit things

| What | File |
|---|---|
| Phone, email, address, socials, team, buy/sell intake links | `src/data/site.js` |
| Marketplace listings | `src/data/projects.json` |
| Knowledge base articles (32, seven sections) | `src/content/knowledge-base/*.md` |
| Blog posts (`/blog/`, starts empty; noindex until the first post) | `src/content/insights/*.md` |
| CORSIA services page copy | `src/data/corsia-service.json` |
| Page layouts | `build.mjs`, `src/lib/layout.mjs` |
| Styles / scripts | `src/assets/css/main.css`, `src/assets/js/main.js` |

To add an article, copy an existing `.md` file, change the front matter at the top and the text below it, then rebuild.
Each project in `projects.json` needs a unique `slug`. Its page is created at `/marketplace/<slug>/`.

## Images

Local photos have an AVIF version next to the JPEG (`src/public/media/`) and are served through `<picture>`. Team photos and logos are WebP. Unsplash photos use `auto=format`, which serves AVIF or WebP to browsers that accept them, with `srcset` so phones get smaller files.

## Content source

Articles, diagrams, listings and service copy were imported from dstechnoverse.com and have since been rewritten. The diagrams were recoloured to this site's palette.

Photographs are from Unsplash. The home page video (`src/public/media/hero-forest.mp4`) is "Aerial View of Dense Forest Canopy" by Chris The Island on Pexels (https://www.pexels.com/video/35724543/), cut to 11.5 s and compressed to 1280px. It plays only on screens 768px and wider, and not when reduced motion or data saver is on. Everyone else sees `hero-forest.avif` / `.jpg`.
